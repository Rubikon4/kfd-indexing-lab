## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

`src/main/kotlin/lab2/ProductSelection.kt`

**Как работает функция и почему выбран такой способ обработки данных?**

Функция построена от условий задачи по входным данным: может быть десятки тысяч товаров и сотни тысяч рекомендаций. Для решаемой задачи это потенциально означает, что необходимо оптимизировать алгоритм, чтобы добиться приемлемой скорости на больших вводных. Исходя из лекционного материала я решил использовать индексацию, хеш-таблицы. Почему не использую Sequence? - он понесет за собой накладные расходы, а раннего выхода (вроде лимита товаров в подборке) задачей не предусмотрено. Сама функция работает следующим образом:

1. индексируется изначальный список товаров по id товара (productsById)
2. создается изменяемый список (пустой) для последующего заполнения товарами из вводных (selection)
3. создается сэт значений id для последующего заполнения ранее встреченными id
4. создается сэт исключений из вводных, который сразу уникализируется, чтобы избежать повторений
5. здесь начинается вторая ступень основной работы - цикл for по рекомендациям (выбран неспроста - по задаче требуется сохранять последовательность основываясь именно на рекомендациях)
6. внутри цикла-прохода происходит несколько проверок: встречался ли ранее id, есть ли в исходном списке продуктов продукт с таким id, объединенная проверка доступности продукта и отсутствия его во вводных исключениях
7. если первые две првоерки завершаются false и последняя true: продукт попадает в список подборки (selection)
8. функция возвращает mutable selection через контракт read-only

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

1. Цикл-проход пробегает по рекомендациям выстраивая подборку на основании порядка в рекомендациях. Уникальность соблюдается при помощи проверки seen.add (seen это hashSet, потому значения там обязаны быть уникальными; add в данном случае проверяет внутри эту уникальность).
2. Последний if в цикле смотрит на доступность продукта по его available свойству и отсутствию продукта в исключениях. Неизвестные товары проверяются вторым if через ?: : если по текущему id внутри индекса продуктов есть продукт - с продуктом можно работать далее, как с не-nullable подтвержденным значением (не-неизвестным)

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях.

**Время выполнения:**

Оценка моего алгоритма: O(p+r+e). Индексация проходит по списку 1 раз (p операций), цикл for один раз проходит по рекомендациям (r действий), хеширование исключений тоже закрывается в один проход (e действий).
Если рассматривать нормальное поведение хеш-таблиц, отсутствие множества коллизий - работу алгоритма можно считать оптимальной для описываемых в задаче масштабов. При возникновении коллизий, например, могут проводиться дополнительные проверки соотношений - это немного, но увеличит работу.

**Дополнительная память:**

В памяти при вызове функции образуется 4 массивных ячейки - крупные таблицы productsById, seen, selection и excludedSet. Размеры ячеек пропорциональны увеличению/уменьшению входных данных и повторов продуктов. От повторов особенно зависит seen: она растет пропорционально увеличению числа уникальных продуктов.
Реальный размер зависит от особенностей работы конкретной JVM. Через О зависимость можно объяснить напрямую: O(p+r+e). Если входные данные вырастут вдвое, занимаемая память вырастет примерно вдвое. Про память результата - прямая зависимость от количества продуктов (k): О(k). Та же логика с увеличением вдвое

### Тесты

В таблице указываются названия тестов или ссылки на них. Один тест может проверять несколько условий.

| Что проверяется | Тесты |
| --- | --- |
| Обычная подборка; порядок рекомендаций отличается от порядка каталога | `selectsAvailableProductsInRecommendationOrder` |
| Повторяющиеся рекомендации и исключения | `selectsAvailableProductsInRecommendationOrder`, `returnEmptyListWithEqualsRecommendationsAndExcludes` |
| Недоступные, исключённые и неизвестные товары | `selectsAvailableProductsInRecommendationOrder`, `returnEmptyListWhenThereAreNoAvailableOrNotExcludedOrNoCorrectProducts` |
| Пустой каталог, пустые рекомендации, пустые исключения | `returnEmptyListWhenEmptyEntry`, `returnsEmptyListWhenThereAreNoRecommendations` |
| Ни один товар не подходит | `returnEmptyListWithEqualsRecommendationsAndExcludes`, `returnEmptyListWhenThereAreNoAvailableOrNotExcludedOrNoCorrectProducts` |
| Входные данные не изменяются; повторные вызовы независимы | `safetyOfEntryObject`, `independenceOfResultsObjects` |

Пустой каталог, рекомендации и исключения проверяются одновременно в `returnEmptyListWhenEmptyEntry`; отдельно пустые рекомендации и исключения проверяются в `returnsEmptyListWhenThereAreNoRecommendations`. Пустой каталог и пустые исключения при непустых остальных входных списках отдельно не проверяются.
